# Спека: Фаза 2 — визуальные варианты лендинга «ПроВожатый»

## Цель

Дать пользователю 3 принципиально разных визуальных направления одного и того же лендинга (контент, структура из 8 экранов и hero-видео не меняются), переключаемых мгновенно на одной странице — чтобы выбрать лучшее направление для дальнейшей полировки.

## Контекст

Фаза 1 закончена: `landing/index.html`, `landing/css/style.css`, `landing/js/script.js` — рабочий лендинг с hero-видео (`assets/hero.mp4`, скраббинг по скроллу через GSAP ScrollTrigger) и reveal-анимациями остальных 7 секций. Дизайн-система Фазы 1 — `references/design-system.md`.

## Решения (из grilling-интервью)

1. **3 варианта.**
2. **Концепции** (визуальный язык различается, контент/структура/DOM — общие):
   - **`warm`** — «Тёплый и доверительный» = текущий вариант Фазы 1 без изменений (дефолт).
   - **`soft`** — «Мягкий и воздушный» — светлая пастельная палитра, крупные радиусы, мягкие тени, спокойные плавные анимации, без засечек нигде.
   - **`bold`** — «Смелый и энергичный» — высокий контраст, тёмный доминирует, крупная жирная типографика, резкие/пружинные анимации.
3. **Механика:** одна HTML-разметка. Переключатель ставит `data-theme="warm|soft|bold"` на `<html>`. Все визуальные различия — через CSS custom properties (плюс JS-пресет анимаций, см. ниже). DOM, порядок и состав секций, раскладка (grid/flex) блоков — **не меняются**.
4. **UI переключателя:** плавающая fixed-панель поверх сайта, 3 кнопки (А/Б/В), видна при скролле на любой секции, переключает мгновенно без перезагрузки, позиция скролла сохраняется. Выбор сохраняется в `localStorage` (`provozhaty-theme`), дефолт при первом визите — `warm`.
5. **Анимации:** стиль scroll-reveal (длительность/ease/дистанция/стаггер) тоже часть визуального языка и отличается по вариантам — задаётся JS-объектом пресетов, читающим текущий `data-theme`. Hero-видео (скраббинг currentTime по скроллу) не меняется ни в одном варианте — это общий ассет.

## Технические требования

1. **Токенизация `style.css`.** Сейчас радиусы карточек и тени захардкожены прямо в правилах (`.step-card`, `.role-card`, `.stat-card`, `.fork-card`, `.safety-item`, `.cta-form` и т.д.). Вынести их в переменные `--radius-card` и `--shadow-card`, использовать переменные во всех этих правилах вместо литералов. `--font-display` уже переменная — просто добавить переопределение по темам. Кнопки/пилюли (`--radius: 999px`) не трогать — они одинаковы во всех трёх вариантах по решению «структура общая».
2. **Блоки тем.** Добавить в `style.css` после `:root{...}`:
   ```css
   [data-theme="soft"]{ /* soft-токены */ }
   [data-theme="bold"]{ /* bold-токены, включая letter-spacing на .hero-title/.h2 если нужно */ }
   ```
3. **Переключатель.** Новый блок в `index.html` (fixed, вне `<main>`, после `</footer>` перед `<script>`):
   ```html
   <div class="theme-switch" id="themeSwitch">
     <button data-theme-btn="warm" class="active" title="Тёплый и доверительный">А</button>
     <button data-theme-btn="soft" title="Мягкий и воздушный">Б</button>
     <button data-theme-btn="bold" title="Смелый и энергичный">В</button>
   </div>
   ```
   Стили — компактная плашка, `position: fixed; right: 20px; top: 50%; transform: translateY(-50%); z-index: 100;` (или низ экрана на мобильном — по усмотрению исполнителя, лишь бы не перекрывала CTA и была доступна с клавиатуры/тач).
4. **JS переключения** в `script.js` (новый блок, не трогать существующую hero/reveal-логику по сути — только читать текущую тему для пресета):
   - При `DOMContentLoaded`: прочитать `localStorage.getItem('provozhaty-theme') || 'warm'`, выставить `document.documentElement.dataset.theme`, подсветить активную кнопку.
   - По клику на кнопку: `document.documentElement.dataset.theme = theme`, сохранить в `localStorage`, обновить `.active` класс.
   - Объект пресетов анимаций (см. таблицы выше) — использовать значения текущей темы при создании `.reveal`-твинов в `script.js` (значения `duration`, `ease`, начальный `y`, `stagger` вместо текущих захардкоженных `0.7 / power2.out / 28 / (i%5)*0.06`).
5. **Не трогать:** hero-видео и его scroll-scrubbing логику, тексты, DOM-структуру секций, форму, 152-ФЗ чекбокс, паддинги/сетку/grid-template-columns — эти правила используют `--wrap`, `--pad-v` и др., но их значения не входят в задачу и не меняются по вариантам (см. решение №3 в grilling).

## Out of Scope (не в этой фазе)

- Impeccable-полировка (Фаза 3).
- Генерация дополнительных фото/видео под варианты (Фаза 4) — все три варианта используют один и тот же `assets/hero.mp4`.
- Панель твиков (шрифты/картинки на лету) — Фаза 5, отдельная и более широкая фича, не путать с переключателем тем.
- Отдельные HTML-файлы на вариант — отклонено в пользу data-theme.

## Приёмка

- Открыть `landing/index.html` в браузере, по умолчанию — тема `warm`, визуально не отличается от текущей Фазы 1.
- Клик по Б/В мгновенно перекрашивает всю страницу (палитра, радиусы карточек, тени, шрифт заголовков) без перезагрузки и без сброса позиции скролла.
- Перезагрузка страницы после выбора Б или В сохраняет выбранную тему (localStorage).
- Hero-видео и его scroll-scrubbing работают одинаково во всех трёх темах.
- Reveal-анимации карточек визуально отличаются по стилю (плавно/мягко в `soft`, резко/пружинисто в `bold`) при скролле через все 7 нижних секций.
- Адаптив (мобильная ширина) не сломан ни в одной теме.
- Форма и чекбокс 152-ФЗ продолжают работать во всех темах.
